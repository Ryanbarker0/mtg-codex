# MTG Codex

A touch-first reference for every keyword ability, keyword action, ability word and rules term in Magic: The Gathering.
Built to sit on a phone or iPad next to a Commander game, so "what does unearth do again?" is answered in two taps.

Nothing in the codex is hand-written.
Every block of text names its source, and the definitions are quoted rather than paraphrased.

## What it does

- Search by name, or by words in the reminder text, glossary and summary.
  Matches on the name rank first.
- Filter to keyword abilities, keyword actions, ability words, rules terms, or everything.
- Each entry shows, in order: reminder text, the Comprehensive Rules glossary line, a plain-English summary, the full rules text of its section with examples, related entries, and example cards from Scryfall ordered by how often they are played in Commander.
- Rule references inside the text ("see rule 702.74") link to the entry that section defines.
- Recently opened entries are kept on the device for quick access during a game.
- Entries have shareable addresses, and the browser back gesture closes them.
- Installs as a standalone app and works offline once loaded.
  Example cards are cached after the first view.
- A Decks section shows every mechanic in a deck, grouped by kind, with the cards that carry each one.
  Tap a mechanic to read its entry, and every entry shows which of your decks use it.
- Add your decks by pasting the text export from Archidekt or Moxfield.
  Cards are looked up on Scryfall in the browser and the deck is kept in IndexedDB on the device, so nothing is hosted, nothing leaves the device, and no decks ship with the app.

## Where the data comes from

The codex is generated by `npm run ingest`, which writes `src/data/codex.json`.
That file is committed, so builds are reproducible and the app never depends on the sources at runtime for its definitions.

1. **Comprehensive Rules**, the official rules document published by Wizards of the Coast.
   The script finds the current text file linked from [magic.wizards.com/en/rules](https://magic.wizards.com/en/rules), parses it into a tree of numbered rules, and takes:
   every named subsection of 701 (keyword actions) and 702 (keyword abilities) as an entry with its rules text and examples;
   every glossary term as either the definition of an existing entry or a new "rules term" entry;
   the rule sections a glossary definition points at, so Monarch shows section 725 and Commander shows section 903;
   and the ability word list from rule 207.2c.
2. **Scryfall**, for the three keyword catalogs.
   They give the spelling as printed on cards and the exact `keyword:` search for example cards, which the app fetches live.
3. **MTG Wiki** ([mtg.wiki](https://mtg.wiki)), for the lead paragraph, the infobox's reminder text, ability type and introducing set.
   Wiki text is licensed CC BY-NC-SA 4.0 and each use links back to the article.

Some names Scryfall tracks have no section of their own in the rules, such as Forestwalk or Friends forever.
These are tied to the section that defines them only on evidence in the sources: the wiki redirects the name to the page of an entry that has rules, the rules spell the name out as a "[type]walk" or "[type]cycling" template, or exactly one keyword section quotes the name the way the rules introduce a variant.
The script logs every link it makes.

Where a source has nothing, the entry says so rather than filling the gap.
Arena-only mechanics, for instance, have a wiki summary and example cards but no rules text, and the entry states that the current rules have no entry under that name.

## Where the decks come from

Decks are pasted as text in the app; none ship with it.
`src/lib/decklist.ts` parses the Archidekt, Moxfield and Arena export formats, including Commander and Maybeboard headings, set codes and collector numbers.
`src/lib/scryfall.ts` looks the lines up on Scryfall in batches, first by printing, then by name, then fuzzily so a typo still resolves, and reports anything it cannot find.
The deck is saved in IndexedDB on the device and can be removed from its page.

Archidekt and Moxfield do not allow browser requests from other origins, which is why the import takes pasted text rather than a URL.

A card's mechanics are Scryfall's `keywords` field, which lists the keyword abilities, keyword actions and ability words on the card with the same names as the codex, so each one maps to an entry by exact name.
Scryfall also lists flavor words there, such as "Grand Summon"; those have no entry and are left out.

That field only covers keywords the card itself has.
A card that grants or names a keyword, such as Zhulodok, Void Gorger giving cascade to other spells, is found by searching its rules text, with reminder text removed, for keyword abilities as whole words.
Those show in a separate "Granted or named in card text" group, and as "also named on" under keywords the deck has outright.
Keyword actions are not searched for this way because their names are everyday verbs in card text.

The pasted list is stored with the deck, and "Check cards on Scryfall again" resolves it afresh, so a deck picks up improvements without being pasted again.

## Refreshing the data

```sh
npm run ingest
```

Run it after a new set releases or the rules are updated, then review the diff of `src/data/codex.json` and commit it.
The script prints the rules' effective date, the counts from each source, every variant link it made, and any keyword that ended up without rules text or a wiki page.

## Running locally

```sh
nvm use
npm install
npm run dev
```

Other scripts:

```sh
npm test          # unit tests (vitest)
npm run lint      # oxlint
npm run format    # prettier
npm run build     # type-check and production build
```

## Deployment

Pushes to `main` build and deploy to GitHub Pages via `.github/workflows/deploy.yml`.
The workflow runs lint, tests and the build before deploying.
The Vite base path is set from the repository name at build time.

On a phone or iPad, open the deployed URL in Safari and use Share, then Add to Home Screen.
The app installs as a standalone PWA and updates itself on the next launch after a deploy.

## Project layout

- `scripts/ingest.ts` builds the codex from the three sources.
- `scripts/lib/comprehensiveRules.ts` parses the rules text file into a tree of rules plus the glossary.
- `scripts/lib/wiki.ts` talks to the wiki's API and parses infoboxes.
- `src/lib/codex.ts` is the shape of the generated data, shared by the script and the app; `src/lib/decks.ts` is the shape of a deck.
- `src/lib/search.ts` ranks entries for a query.
- `src/lib/scryfall.ts` fetches example cards and resolves pasted decklists.
- `src/lib/decklist.ts` parses pasted decklists; `src/lib/importDeck.ts` turns a resolved list into a deck.
- `src/lib/storage.ts` and `src/state/useUserDecks.ts` keep imported decks in IndexedDB.
- `src/components/` holds the list, the entry view, the rules renderer, the card viewer and the deck screens.
